cipherstash_eql_v4 (Resource)¶

Install CipherStash EQL v4, the PostgreSQL types and functions that store, compare and index encrypted values, into one database. The provider's database settings choose the server and role; the role that installs EQL owns every EQL object.

The provider contains the installer for each supported version: the eql-v4-install.sql asset of the matching cipherstash/stack Go release, checked against its SHA-256. Create runs it in one transaction with search_path = public, under the same advisory lock as the stash CLI's installer. It refuses, changing nothing, if the database already has an eql_v4 or eql_v4_internal schema (import it instead), if pgcrypto is installed in a schema other than public or extensions, or if the role lacks CREATE on the database or on public. After the installer runs, it rolls back unless eql_v4.version() matches and, when require_ore is true, the ORE operator class exists.

Install pgcrypto before EQL, for example with a postgresql_extension resource that this resource depends on. Otherwise the installer creates it in a new extensions schema, and every role that compares ORE-encrypted values also needs USAGE on that schema.

EQL issues no grants. Roles that query encrypted columns need USAGE on both schema and internal_schema; grant it with another provider, such as postgresql_grant, referencing these attributes so Terraform installs EQL first.

Changing version to a later release upgrades EQL in one transaction under the same lock. The new installer drops and re-creates both schemas, and the provider restores what that removes: the grants on both schemas and their routines and types, the default privileges in them and, when allow_index_rebuild is true, the indexes that call EQL functions, with their comments and CLUSTER marks. It refuses, changing nothing, to move to an earlier release; while any other object outside EQL depends on EQL, such as a view, policy or constraint that calls an EQL function, or an index on a partitioned table, a materialized view or another session's temporary table, in a non-default tablespace or with a statistics target; while indexes need rebuilding and allow_index_rebuild is false; or if the role lacks the privileges of the owner of the EQL objects, of the tables whose indexes it rebuilds, or of the roles whose default privileges it restores. Tables whose indexes it rebuilds are locked until the upgrade commits. Routines and types that are new in the release get what the restored default privileges grant, as if they had been created after them. Restored grants record the database role as grantor. To upgrade from a version this provider does not ship, upgrade by hand as the README describes.

Destroy uninstalls EQL in one transaction under the same lock. It refuses, changing nothing, while any column uses a public.eql_v4_* domain, while any object outside EQL depends on it (such as an index or view that calls an EQL function), if the role lacks the privileges of the owner of the EQL schemas or of the domains and functions EQL adds to public, or if the provider has no uninstaller for the version the database reports, which planning already rejects, before Terraform destroys anything else. Otherwise it runs that release's eql-v4-uninstall.sql, which drops both schemas, then drops the domains and functions it leaves in public, without CASCADE. pgcrypto and the extensions schema stay. To stop managing the installation without changing the database, use a removed block that sets lifecycle { destroy = false }.

Schema¶

Required¶

  • database (String) Name of the database to install EQL into, on the server from the provider's database settings. Changing this value replaces the resource: destroy uninstalls EQL from the old database, under the same refusals as any destroy, and create installs it in the new one.
  • version (String) EQL version to install, as eql_v4.version() reports it, such as go-0.1.0-rc.3 for the installer released with cipherstash/stack Go v0.1.0-rc.3. It must be a version compiled into this provider: go-0.1.0-rc.2, go-0.1.0-rc.3. Refresh reads the installed version, so an installation changed outside Terraform shows as a difference. Changing it to a later version upgrades EQL; changing it to an earlier one is rejected.

Optional¶

  • allow_index_rebuild (Boolean) Whether an upgrade may drop and rebuild the indexes that call EQL functions, which the installer drops. While false, an upgrade refuses when such indexes exist. Defaults to false. Changing it only updates state.
  • require_ore (Boolean) Whether Create rolls back when the installer cannot create the ORE operator class, which needs a superuser or Amazon RDS rds_superuser. Without it the installer disables the 20 ORE-backed domains and still succeeds. Defaults to true. Changing it only updates state.

Read-Only¶

  • id (String) The database name. Use the database name to import an existing installation.
  • internal_schema (String) The schema of EQL's internal functions, eql_v4_internal. Roles that query encrypted columns need USAGE on it as well, because EQL functions run with the caller's privileges.
  • ore_available (Boolean) Whether the ORE operator class exists and no ORE domain is disabled.
  • owner (String) Role that owns schema eql_v4: the role that installed EQL.
  • pgcrypto_schema (String) Schema of the pgcrypto extension, which EQL's ORE comparisons call. Null when pgcrypto is not installed.
  • schema (String) The EQL schema, eql_v4. Reference it in grants so Terraform installs EQL before granting on it.
  • sha256 (String) SHA-256 of the installer for version, matching the release asset. Null after refresh finds a version this provider has no installer for.
